Варіант 6. Лотерея з призовим фондом

1. ЩО РЕАЛІЗОВАНО

Окремий проєкт Hardhat із двома пов'язаними смартконтрактами.
Lottery приймає внески в Ether, зберігає учасників і призовий фонд.
PrizeDistributor організовує розіграш, визначає переможця, отримує фонд
із Lottery та виплачує його переможцю за підписаною ним транзакцією.

Інтерфейс створено на tkinter. Він показує стан лотереї, ціну квитка,
учасників, баланс акаунта, організатора, переможця та журнал операцій.
Приватний ключ вводиться у поле з прихованими символами, після підключення
поле очищається. Ключ використовується тільки в пам'яті для підписання
транзакцій. Кнопка «Забути ключ» видаляє посилання на акаунт із програми.
Ключі та seed-фрази в проєкті не зберігаються.

Умови: один квиток на адресу, квиток коштує 0,01 ETH, щонайменше два
учасники для розіграшу. Один деплой відповідає одній лотереї.
Комісії організатору немає: весь облікований фонд належить переможцю.
Газ транзакцій оплачується окремо тестовими ETH акаунта.

scripts/export-contracts.mjs — експорт справжніх ABI та адрес після деплою.

python/app.py — віконний інтерфейс tkinter.
python/client.py — читання блокчейну та локальне підписання транзакцій.
python/contract_addresses.json — адреси контрактів локального деплою.
python/abi/ — ABI контрактів, сформовані компілятором.

python/py_commands.txt — команди Python.

.github/workflows/check.yml — автоматичні перевірки на GitHub.

3. ПЕРШИЙ ЗАПУСК НА WINDOWS

Потрібні Node.js 22.13+ (гілка 22 LTS) і Python 3.12 з tkinter.
У Windows tkinter входить до стандартного встановлення Python.
Відкрити папку fintech-lottery у PyCharm або терміналі.
Усі наведені нижче команди виконувати з кореня проєкту.

Встановлення залежностей:

npm install
python -m venv python/.venv
.\python\.venv\Scripts\python.exe -m pip install -r python/requirements.txt

Папка .venv створюється локально і не переноситься між комп'ютерами.
node_modules та .venv не потрібно додавати до GitHub чи архіву.

Компіляція та перевірка контрактів:

npx hardhat compile
npx hardhat test

Термінал 1 — запустити блокчейн і залишити його працювати:

npx hardhat node

Термінал 2 — задеплоїти обидва контракти та оновити ABI й адреси:

npm run deploy

Після цього запустити вікно:

.\python\.venv\Scripts\python.exe python/app.py

У PyCharm ці операції також доступні через збережені конфігурації запуску.
Не потрібно повторно виконувати npm init або hardhat --init у готовому
проєкті: ці команди в commands.txt наведено для створення нового проєкту.

4. ДЕМОНСТРАЦІЯ ВИКЛАДАЧУ

1) Натиснути «Підключитися». Стандартний RPC: http://127.0.0.1:8545.
   Має бути статус «Прийом внесків», ціна квитка 0,01 ETH і 0 учасників.

2) У терміналі Hardhat знайти тестовий Account #1. Скопіювати його
   приватний ключ у приховане поле вікна та натиснути «Використати ключ».
   Натиснути «Придбати квиток». З'явиться перший учасник і фонд 0,01 ETH.

3) Так само підключити тестовий Account #2 і придбати ще один квиток.
   У списку буде два учасники, фонд — 0,02 ETH.

4) Підключити ключ тестового Account #0: це організатор за стандартного
   деплою Ignition. Адресу організатора також показано у вікні.
   Натиснути «Розпочати розіграш». Нові внески більше не приймаються.

5) Натиснути «+3 блоки Hardhat». Це створить порожні тестові блоки,
   необхідні для демонстрації очікування майбутнього блоку.
   Потім натиснути «Визначити переможця».

6) Подивитися адресу переможця та підключити ключ відповідного Account
   #1 або #2. Поле «Отримувач ETH» автоматично міститиме адресу акаунта.
   Натиснути «Отримати виграш». Приз до отримання стане 0 ETH.
   Баланс переможця збільшиться на приз мінус газ цієї транзакції.

7) Показати перевірки: повторний квиток відхиляється, сторонній акаунт
   не може почати розіграш, чужий акаунт не може отримати виграш,
   повторна виплата не дозволена. До розіграшу організатор може скасувати
   лотерею; тоді кожен учасник повертає свій внесок кнопкою повернення.

Не вставляти приватні ключі у звіт, GitHub, скриншоти або файли проєкту.
Використовувати тільки тестові ключі локального Hardhat.

5. ЛОГІКА ТА ОБМЕЖЕННЯ

Стани: Open -> Drawing -> Finished; або Open/Drawing -> Cancelled.
Організатор починає розіграш, але не передає довільну адресу переможця.
Для вибору використовується хеш заздалегідь визначеного майбутнього блоку.
Після настання цього блоку будь-який акаунт може завершити розіграш.
Якщо минуло понад 256 блоків від цільового, розіграш можна скасувати,
а внески — повернути. Після визначення переможця виплата не має строку.

Виграш отримується окремою транзакцією. Це дозволяє переможцю обрати
іншу адресу отримувача, якщо його контракт не приймає Ether. Невдала
виплата не обнуляє право на приз. Аналогічно працює повернення внеску.
Зміни обліку виконуються перед зовнішнім переказом; додано захист від
повторного входу. Організатор не має функції зняття чужого фонду.

Це навчальний проєкт для локального Hardhat. Хеш блоку не є надійним
джерелом випадковості для лотереї зі справжніми коштами: валідатори можуть
впливати на блоки. Для виробничої системи потрібне перевірюване джерело
випадковості, наприклад VRF. Python-клієнт приймає лише chainId 31337.

Hardhat за замовчуванням створює блоки при транзакціях, тому просто
очікування кількох секунд не замінює кнопку створення тестових блоків.
Після перезапуску вузла попередній стан зникає. Потрібно повторити деплой
та експорт. Якщо Ignition повідомляє про старий журнал після перезапуску,
виконати в новому локальному блокчейні:

npx hardhat ignition deploy ignition/modules/Lottery.ts --network localhost --reset
node scripts/export-contracts.mjs
